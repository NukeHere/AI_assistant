# Архитектура тестовой сборки

Первый этап намеренно простой: обычное desktop-приложение на ПК и обычная LLM.
История переписки хранится в приложении, а сервер получает её целиком при каждом
запросе.

## Поток запроса

```text
Desktop app
  -> история переписки + новое сообщение
  -> HTTPS-запрос с bearer token
  -> FastAPI server
  -> LLM API
  -> ответ клиенту
```

На этом этапе сервер ничего не обязан помнить между запросами. Он просто
защищает ключ модели и приводит все клиенты к единому API.

## Что отложено

- Долгая память.
- ANA/ALIEN как активные режимы продукта.
- Голосовой режим.
- Телефонный клиент.
- Интеграции с календарём, почтой и файлами.
- Синхронизация резервных копий в Яндекс Диск.

## Почему Яндекс Диск не база данных

Яндекс Диск лучше использовать как резервное и файловое хранилище: аудио,
изображения, видео, документы, архивы и копии базы. Живая память должна быть в
SQLite на MVP или Postgres после выноса на сервер.

В проекте уже есть заготовка резервного копирования SQLite, но для первого
MVP она не нужна. Позже на сервере эту папку можно синхронизировать с Яндекс
Диском через WebDAV или rclone каждые 12 часов. Храним последние 10 копий.

## Хостинг с оплатой из России

Для MVP с минимальной болью по оплате лучше смотреть российские VPS/облака:

- Timeweb Cloud: простой VPS, минимальный тариф около 900 рублей в месяц.
- Selectel: облачные серверы примерно от 948 рублей в месяц, почасовая оплата.
- Yandex Cloud: российский провайдер, но тарификация в долларах; оплату надо
  проверять под конкретный аккаунт и карту.
- VK Cloud: потенциальный вариант, но цены и удобство для маленького личного
  проекта нужно проверить отдельно перед выбором.

Для совсем бесплатного теста можно разворачивать локально на ПК. Для настоящего
"всегда рядом" бесплатные зарубежные платформы хуже: часть сервисов засыпает,
часть неудобно оплачивать, часть ограничена по исходящим запросам.

## Что перенесено из DeepGroupManager.py как идея

- История сообщений хранится по ключу беседы.
- Есть отдельное состояние режима.
- Есть слой сборки prompt перед вызовом модели.
- Есть фоновая задача.
- Есть быстрый режим mock-ответов без реального API.

Что не переносится:

- Токены в коде.
- Смешивание Telegram-логики, памяти, prompt и модерации в одном файле.
- Непрозрачная глобальная mutable-логика.
