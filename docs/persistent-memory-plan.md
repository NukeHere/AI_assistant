# Постоянная память без зависимости от ПК

Сейчас SQLite хранится в DATABASE_PATH на временном диске Render.
Файлы бесплатного сервиса теряются при перезапуске, деплое и остановке из-за простоя.
Локальный backup-agent не гарантирует восстановление, если ПК выключен.
Источник: https://render.com/docs/free

Рекомендуемая архитектура: PostgreSQL отдельно от процесса Render. Пользователи,
Telegram-привязки, диалоги, ячейки памяти и таймеры записываются туда сразу в транзакциях.
ПК скачивает резервные копии, но не является источником истины.

Бесплатный Render Postgres истекает через 30 дней и для постоянной памяти не подходит.
Нужен провайдер постоянного PostgreSQL или небольшой сервер с постоянным диском
и удобной оплатой. Провайдер, стоимость и строка подключения пока не выбраны.
Альтернатива с минимумом правок: платный Render с persistent disk для SQLite.

План перехода:

1. Выгрузить актуальную SQLite и доступные резервные копии до переноса.
2. Добавить PostgreSQL-реализацию Storage, миграции схемы и DATABASE_URL.
3. Импортировать сообщения по message_uid, таймеры по timer_uid, привязки по Telegram ID.
4. Сверить данные и проверить перезапуск Render при выключенном ПК.
5. Настроить регулярные резервные копии вне сервера БД и проверить восстановление.

Это план: текущий Telegram-патч не переводит БД на PostgreSQL и не устраняет потерю SQLite.

Новые групповые истории используют отдельные профили tg-group-<chat_id>.
Старые записи смешаны с личными чатами и не имеют надёжной привязки к исходной группе.
Автоматически публиковать их нельзя: переносить можно только записи с подтверждённым источником.
Резервное копирование нужно расширить на все профили, включая группы, а не только primary-user.
