# Smart memory

Текущий слой памяти состоит из двух уровней.

## Ручная память

Пользователь может явно сказать:

```text
запомни: мой основной проект называется AI Assistant
/remember я предпочитаю короткие технические ответы
/memory
```

Такие записи сохраняются как важные memory-cell.

## Автоматическая память модели

System prompt даёт модели private memory functions. Если модель понимает, что
факт нужно сохранить, она добавляет в конец ответа JSON-блок:

```text
```assistant_memory
{"remember":[{"kind":"important","summary":"очень краткая выжимка","full":"полная извлечённая информация","topics":["topic"],"importance":5}]}
```
```

Сервер вырезает этот блок из ответа, пользователь его не видит, а запись уходит
в SQLite.

## Summary и full memory

- `summary` — короткая выжимка, которую можно дешево добавлять в prompt.
- `full_content` — полная информация, которую сервер отдаёт модели только при
  явной необходимости.
- `topics` — темы для подбора.
- `importance` — важность от 1 до 5.

Важные записи подмешиваются почти всегда. Тематические записи выбираются по
лексическому совпадению и локальному embedding-score.

## Recall полной памяти

Если модель видит короткую выжимку и понимает, что ей нужна полная запись, она
может запросить:

```text
```assistant_memory
{"recall":["тема или краткое описание"]}
```
```

Сервер найдёт подходящие full-записи, сделает второй проход модели и вернёт
пользователю уже финальный ответ.

## Ограничение MVP

Сейчас embeddings локальные и бесплатные: это стабильный hash-vector без внешних
зависимостей. Он лучше простого поиска по словам, но не равен настоящим semantic
embeddings. Следующий шаг — подключить embedding API или локальную embedding
модель, когда выберем провайдера.
