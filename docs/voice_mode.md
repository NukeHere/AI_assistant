# Voice mode ideas

Практичный голосовой режим лучше делать слоями, чтобы не ломать уже рабочий чат.

## MVP voice push-to-talk

Первый вариант: кнопка микрофона в Android-клиенте и desktop-клиенте.
Пользователь нажимает кнопку, приложение записывает фразу, распознаёт её в текст,
отправляет обычный `/v1/message`, а ответ показывает текстом. Это самый дешёвый
и управляемый режим.

## Wake word / ручной вызов

Следующий слой: локальная активация по слову вроде «Ана» или «Ассистент».
Важно делать распознавание wake word локально на устройстве, чтобы телефон не
слал постоянный аудиопоток на сервер. Сервер должен получать только уже
подтверждённую команду.

## Streaming conversation

Позже можно добавить режим живого разговора:

- клиент постоянно слушает короткими окнами;
- локально определяет конец фразы;
- отправляет transcript на `/v1/message` с `input_type = voice_transcript`;
- получает текстовый ответ;
- TTS читает ответ голосом ANA или ALIEN.

## Голоса персонажей

ANA: чистый спокойный голос, минимальная эмоциональность, короткие паузы.
ALIEN: чуть более низкий/слоистый голос, лёгкая реверберация на клиенте, но без
потери разборчивости. Эффект должен помогать присутствию, а не мешать понимать
команды.

## Интеграции

Когда базовый голос стабилен, можно добавлять функции:

- напоминания и календарь;
- почта и краткая сводка входящих;
- заметки в память через «запомни»;
- быстрые команды ПК;
- ежедневный утренний briefing;
- режим hands-free для телефона.

Главный принцип: аудио остаётся на устройстве настолько долго, насколько это
возможно. На сервер уходит текст и только те команды, которые пользователь
действительно хотел отправить.
